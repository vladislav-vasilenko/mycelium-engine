## Решение

Начинаем с **Rust, нативного Metal 4 и MSL**. Rust подходит для общего кода мира и симуляции. В safe Rust компилятор проверяет владение и заимствования. `objc2-metal` даёт доступ к Metal 4, где мы сами ведём очереди, барьеры, резидентность и время жизни GPU-ресурсов. После игрового среза подключаем **нативный D3D12 и HLSL** через Rust-биндинги Windows. [Владение в Rust](https://doc.rust-lang.org/book/ch04-01-what-is-ownership.html) · [MTL4CommandQueue в objc2-metal](https://docs.rs/objc2-metal/0.3.2/objc2_metal/trait.MTL4CommandQueue.html) · [D3D12 в windows-rs](https://microsoft.github.io/windows-docs-rs/doc/windows/Win32/Graphics/Direct3D12/index.html)

| Вариант | Что даёт проекту | Компромисс |
| --- | --- | --- |
| Rust + Metal 4 | Системное программирование GPU на текущем Mac. Код симуляции переедет на Windows | Графический бэкенд Windows добавляем отдельным этапом |
| Rust + wgpu | Один рендерер для типовых vertex, fragment и compute-эффектов на нескольких нативных бэкендах | Управление GPU идёт через API wgpu, нативные стадии зависят от бэкенда и набора возможностей |
| Swift + Metal 4 | Прямой доступ к API Apple и ARC для ссылочных объектов | Путь до Windows потребует отдельной интеграции. Цена ARC зависит от числа операций со ссылками. [Рекомендации Swift по производительности](https://github.com/swiftlang/swift/blob/main/docs/OptimizationTips.rst#using-container-types-efficiently) |
| C++ + нативные API | Прямой доступ к Metal и D3D12, RAII для ресурсов | Корректность времени жизни заимствованных указателей контролирует автор кода |

По исходникам wgpu 30.0.1 его Metal-бэкенд использует `MTLCommandQueue`. Для mesh на Metal и DX12 эта версия требует нативного shader passthrough. Это делает wgpu интересным для сравнения одного прохода, а прямой Metal 4 — основой для упражнения с `MTL4CommandQueue` и нативными стадиями. [Metal-бэкенд wgpu](https://github.com/gfx-rs/wgpu/blob/v30.0.1/wgpu-hal/src/metal/mod.rs) · [Mesh в wgpu 30.0.1](https://docs.rs/wgpu/30.0.1/wgpu/struct.Features.html#associatedconstant.EXPERIMENTAL_MESH_SHADER) · [Основы Metal 4](https://developer.apple.com/documentation/metal/understanding-the-metal-4-core-api)

Vulkan пересматриваем, если Linux станет целью. На macOS доступность его возможностей зависит от конкретного слоя, например MoltenVK, и устройства. [MoltenVK Runtime User Guide](https://github.com/KhronosGroup/MoltenVK/blob/main/Docs/MoltenVK_Runtime_UserGuide.md)

## Консоли

PS5 Pro и другие консоли в текущий объём не входят. SDK консолей выдаются зарегистрированным разработчикам по NDA, официальной поддержки Rust в них нет, поэтому конкретный бэкенд сейчас не планируем. Чтобы не закрыть этот путь:

- `World` и `Game` не зависят от графического бэкенда и не опираются на единую память Apple silicon. Данные попадают на GPU через явный upload, этап [06](06-d3d12-port.md) проверяет это на дискретном GPU.
- Для каждого эффекта фиксируем смысл входов и выходов и эталонные значения, чтобы его можно было переписать на другом языке шейдеров и сверить.
- Общий RHI выделяем только по факту двух работающих бэкендов.

Решение пересматриваем при получении доступа к SDK.

## Исходники шейдеров

- Metal — `shaders/metal/*.metal` на MSL. В Debug компилируем исходник через API Metal для быстрой перезагрузки. Для офлайн-сборки используем Metal Toolchain и `.metallib`.
- D3D12 — `shaders/d3d12/*.hlsl`. DXC собирает HLSL в DXIL. Сравниваем реализацию эффекта с MSL на одних входных данных. [DirectX Shader Compiler](https://github.com/microsoft/DirectXShaderCompiler)
- WGSL используем в [контрольном опыте с wgpu](07-shader-labs.md#wgpu-и-общий-исходник). Это стандарт WebGPU, который нативный wgpu транслирует в код бэкенда, например в MSL на Mac. Один общий исходник на Slang имеет смысл проверить после появления двух нативных реализаций. [Спецификация WGSL](https://www.w3.org/TR/WGSL/) · [Входы и выходы Naga](https://github.com/gfx-rs/wgpu/blob/v30.0.1/naga/README.md)

## Проверить перед первым билдом

1. Проверить `rustc --version` и `cargo --version`. Для проекта выбрать стабильный Rust с edition 2024, зафиксировать версию toolchain и `Cargo.lock` при создании приложения. Фактическое состояние среды записывается в [отчёт](../reports/00-platform.md).
2. Цель первого билда — arm64, macOS 26 или новее, SDK macOS 26 или новее. Для офлайн-сборки проверить `xcrun metal --version`. При недостающем Metal Toolchain получить компонент через Xcode → Settings → Components или `xcodebuild -downloadComponent MetalToolchain`. [Установка компонентов Xcode](https://developer.apple.com/documentation/xcode/downloading-and-installing-additional-xcode-components)
3. В этапе 01 вывести в лог имя адаптера, версию ОС и результат `supportsFamily(MTLGPUFamilyMetal4)`. Для лабораторий отдельно проверить семейство GPU, доступные форматы, лимиты и создание нужного pipeline. Записать `supportsRaytracing` и `supportsRaytracingFromRender` отдельно. Доступность лаборатории выводить в диагностике с причиной и базовым путём. [MTLGPUFamily](https://developer.apple.com/documentation/metal/mtlgpufamily) · [Metal Feature Set Tables](https://developer.apple.com/metal/capabilities/)

## Границы в коде

| Часть | Ответственность |
| --- | --- |
| `Platform` | Окно, часы, ввод, файловые пути, поверхность вывода. Передаёт нативный дескриптор только при создании бэкенда |
| `World` | Тайлы высот, биомы, течение, столкновения, идентификаторы объектов и точки интереса |
| `Game` | Игрок, состояние задания, экспозиция спор, события грибницы и сохранения. Читает данные мира через CPU-запросы |
| `Renderer` | Читает снимок `RenderScene` и параметры `View`. Владеет GPU-ресурсами, проходами, синхронизацией и выводом кадра |

- Первый рендерер конкретный. Общая граница — данные сцены, камера, форматы и смысл проходов. Нативные типы и `unsafe` вызовы сосредоточены в платформенном модуле и бэкенде. Когда D3D12 повторит несколько реальных проходов, выделим подтверждённые общие операции.
- Мир и игра обновляются фиксированными шагами. CPU определяет столкновения, результаты квестов и интерактивные объекты. GPU получает снимок и отвечает за визуальные поля, LOD, отсечение и массовые частицы. Отключение эффекта сохраняет тот же результат игрового тика.
- Договориться о единицах сразу. Метры, секунды, правая система координат, Y вверх, камера в сторону −Z. Векторы-столбцы, преобразование `clip = P * V * M * p`, глубина клипа [0, 1]. Основная камера использует reversed-Z с очисткой глубины в 0 и тестом `GreaterEqual`. Зафиксировать направление обхода лицевой стороны тестовой геометрией. Начало экранных координат в левом верхнем углу.
- Описать раскладку общих GPU-данных через `#[repr(C)]`, фиксированные целые типы, явное выравнивание и смещения. Проверять stride и offsets на CPU и в маленьком GPU-тесте. Линейное освещение в HDR-буфере, одно преобразование в sRGB при выводе.
