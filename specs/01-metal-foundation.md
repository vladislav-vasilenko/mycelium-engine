# 01. Основа Metal 4

[К карте этапов](README.md)

**Зависит от** — [00. Платформа и архитектура](00-platform.md).

**Результат** — приложение с управляемой камерой, глубиной и текстурой, записанной compute-проходом в том же кадре.

**По книге** — [время, камера и кадр](reading-guide.md#01-кадр).

## Порядок реализации

1. Создать приложение Cargo. Использовать `winit` для окна и ввода, в платформенном коде привязать `CAMetalLayer` к `NSView` на главном потоке. GPU-объекты создавать через `objc2-metal`. Для Debug компилировать MSL из `shaders/metal/` через `MTLDevice`. При наличии Metal Toolchain добавить офлайн-сборку `.metallib` для Release. Подписать pipeline и ресурсы для GPU capture. [Компиляция библиотеки Metal из исходника](https://developer.apple.com/documentation/metal/mtldevice/makelibrary%28source%3Aoptions%3A%29)
2. Создать устройство, проверить Metal 4 и сделать очередь `MTL4CommandQueue`. Показать цвет очистки и треугольник. Для подачи использовать `MTL4CommandBuffer` и `MTL4CommandAllocator`, для binding — `MTL4ArgumentTable`, для резидентности — `MTLResidencySet`. Перед commit поставить ожидание drawable, после commit просигналить drawable и вызвать present по схеме Apple. [Пример треугольника Metal 4](https://developer.apple.com/documentation/metal/drawing-a-triangle-with-metal-4)
3. Начать с одной очереди для render, compute и copy. Выделить два слота кадра с собственным аллокатором, изменяемыми таблицами аргументов и диапазоном upload в `StorageModeShared`. Scratch-ресурсы кадра держать в слоте, общие записываемые ресурсы синхронизировать и между кадрами. Возвращать слот и высвобождать связанные ресурсы по завершению GPU через `MTLSharedEvent`. При таймауте пропустить запись в занятый слот и вывести диагностику. При свёрнутом окне или отсутствии drawable пропускать вывод, при resize пересоздавать цели по пиксельному размеру и отложенно освобождать старые.
4. Добавить индексированный куб, `Depth32Float` и HDR-цель `RGBA16Float`. Вывести её через fullscreen fragment pass с тонмаппингом и sRGB drawable. Проверить фронтальную сторону, глубину перекрытия двух примитивов и матрицы камеры. Для временного теста использовать простое освещение.
5. Ввести ввод от первого лица. Движение WASD, относительный поворот мышью, захват курсора по клику и освобождение по Escape или потере фокуса. У симуляции фиксированный шаг 1/60 с, у рендера интерполяция между последними состояниями. Ограничить догоняющие тики после паузы и очищать зажатые клавиши при смене фокуса. На этом этапе камера свободная, ходьба по грунту появится на этапе 02.
6. Написать compute-проход, который рисует диагностический узор в текстуру, и показать её на кубе. Добавить явную зависимость compute write → fragment read. При фиксированном времени сравнить несколько пикселей с эталоном. Readback запускать по запросу и читать после сигнала завершения. Для работы через `MTL4CommandQueue` указывать зависимости явно. [Синхронизация ресурсов Metal](https://developer.apple.com/documentation/metal/resource-synchronization)
7. Добавить ручную перезагрузку MSL по F5 в Debug. Компилировать изменённую библиотеку и новый pipeline, сверять схему аргументов и подменять pipeline на границе кадра после успеха. При ошибке показывать файл, стадию и диагностику компилятора, продолжать рисовать предыдущим pipeline. Удерживать старые GPU-ресурсы до завершения использующих их кадров.

## Описание проходов

После связки compute и растера ввести небольшой список проходов кадра. Каждый проход объявляет имя, тип, чтения, записи, стадию, load/store вложений и функцию записи команд. Начать с порядка добавления и учёта зависимостей на весь ресурс. Валидировать чтение до записи и разрешённые импортированные данные. Разбирать RAW, WAR и WAW, включая смену назначения `compute output → indirect arguments` в следующих этапах. Бэкенд кодирует барьеры по семантике своего API. Общий граф и оптимизации времени жизни оценим на реальном порту.

## Проверка готовности

- При запуске видны GPU, версия ОС, размер кадра и результат проверки Metal 4. При недоступном Metal 4 приложение показывает понятную ошибку.
- Куб отображается стабильно после resize, сворачивания и возврата фокуса. Мышь работает после повторного захвата. Перекрытие примитивов и результат compute соответствуют эталону.
- Правка цвета в MSL становится видна после F5. При синтаксической ошибке сцена продолжает отрисовываться с предыдущим pipeline и появляется диагностика. После исправления новый pipeline подхватывается в том же запуске.
- Xcode GPU capture показывает compute, барьер, raster и tone map. Metal API Validation выдаёт 0 ошибок. CPU ждёт GPU только в местах, где требуется завершение, например перед повторным использованием занятого слота. [Metal Debugger](https://developer.apple.com/documentation/xcode/metal-debugger)
