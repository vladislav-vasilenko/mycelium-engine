# 02.3. Отсечение и уровни детализации

[К этапу 02](02-terrain-biomes.md) · [К карте этапов](README.md)

**Зависит от** — [02.1. Данные мира и ходьба](02-1-terrain-data.md).

**Результат** — рисуются только тайлы в поле зрения. Детализация рельефа выбирается по экранной ошибке через quadtree: вблизи сетка 1 м, вдали — всё грубее, без отдельных мешей LOD и без щелей. Переход между уровнями плавный (морфинг), без «прыжков» вершин. Та же схема годится для мира 4 × 4 км и больше в [08.1](08-1-world-partition-streaming.md).

**По книге** — [подготовка тайлов и структура мира](reading-guide.md#02-ландшафт).

## Контракт

Потребляет из 02.1: `Tile`, вершины `TerrainVertex` уровня LOD 0, `Ground` для контрольных сравнений.

Создаёт:

- `TileBounds { min, max, max_error[lod] }` — границы тайла и наибольшее отклонение высоты каждого уровня от LOD 0. Считаются один раз при запекании.
- `TerrainQuadtree` — дерево квадратов над картой: корень — вся карта, лист — тайл 64 м или его четверть. У каждого узла есть границы по высоте и экранная ошибка. Используется для выбора детализации и пространственных запросов («какие тайлы в радиусе», «какой тайл под точкой»).
- `TerrainPatch { origin, size, lod, morph_range }` — элемент списка видимых узлов кадра (CDLOD). Все узлы рисуются одной общей сеткой-патчем, вершинный шейдер берёт высоты из текстуры высот и плавно сдвигает вершины к грубому уровню в зоне морфинга.
- Текстура высот рельефа для вершинного шейдера (сейчас высоты лежат в `TerrainVertex`) и общая сетка патча 33 × 33.
- Отладочный вид выбранного уровня в `TerrainView`.

## Порядок реализации

1. **Frustum culling на CPU.** Отсекать тайлы по пирамиде видимости через `TileBounds` (проверка AABB против шести плоскостей). Выводить число видимых тайлов и треугольников в заголовок окна. Для острова 1024 м это первый и самый дешёвый выигрыш: сзади и сбоку камеры отпадает 60–75 % тайлов.
2. **Плоские уровни как базовая линия.** Уровни 65/33/17 по экранной ошибке с гистерезисом, разница соседей не больше одного уровня, стыки — юбками, затем вариантами индексов по маске краёв. Оставить переключателем для сравнения.
3. **Quadtree и CDLOD.** Построить `TerrainQuadtree`. Обход сверху вниз: узел, ошибка которого на экране меньше порога (например 1 пиксель при 1080p), рисуется целиком, иначе спускаемся к детям. Узлы вне фрустума отбрасываются вместе с поддеревом. Высоты переходят в текстуру (R32Float, общий источник с 02.1), все узлы рисуются одним instanced draw общей сетки 33 × 33. В зоне морфинга на внешней трети радиуса уровня вершины плавно сдвигаются к позициям грубого уровня, поэтому щелей нет без юбок. [Filip Strugar, CDLOD](https://github.com/fstrugar/CDLOD/blob/master/cdlod_paper_latest.pdf)
4. **Совпадение с ходьбой.** Вблизи игрока (радиус ≥ 64 м) уровень всегда LOD 0, поэтому `SampleGround` по-прежнему совпадает с видимой поверхностью. Проверка лучом по `SampleGround` из самопроверки остаётся.
5. **Отладка.** Вид «уровень детализации» в `TerrainView`, рамки узлов quadtree, счётчики узлов и треугольников по уровням.

Отсечение перекрытием (гора закрывает долину) — в [02.6](02-6-occlusion-culling.md). Подгрузка частей дерева с диска и мир больше одной карты — в [08.1](08-1-world-partition-streaming.md). Тесселяция и displacement вблизи — в [08.4](08-4-procedural-on-the-fly.md).

## Проверка готовности

- CPU-тест frustum culling: тайл целиком вне пирамиды отбрасывается, тайл на границе остаётся; на 6 контрольных камерах число видимых тайлов совпадает с перебором.
- CPU-тест CDLOD: на границе уровней вершины мелкого узла после морфинга лежат на рёбрах грубого, Т-образных щелей нет. Соседние узлы отличаются не больше чем на один уровень.
- Для группы контрольных камер глубина с LOD совпадает с LOD 0 в пределах допуска, заданного экранной ошибкой. В радиусе 64 м от игрока — LOD 0, проверка `SampleGround` проходит.
- На записи движения вдоль тропы нет открытых щелей и заметных «прыжков» вершин. При неподвижной камере выбор узлов не меняется от кадра к кадру.
- Число видимых узлов и треугольников по уровням и время CPU обхода записаны в отчёте. Цель на острове 1024 м — меньше 0,4 млн треугольников рельефа при прежнем виде вблизи, обход дерева ≤ 0,2 мс CPU.
