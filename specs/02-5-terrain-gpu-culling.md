# 02.5. GPU-driven: выбор и отсечение кластеров и экземпляров на GPU

[К этапу 02](02-terrain-biomes.md) · [К карте этапов](README.md)

**Зависит от** — [02.3. Кластерный рельеф](02-3-terrain-lod.md): иерархия кластеров и выбор на CPU как эталон. Экземпляры растений и импосторы — после [02.4. Растительность](02-4-vegetation.md); кластерная часть от 02.4 не зависит.

**Результат** — CPU больше не перебирает кластеры: GPU сам обходит иерархию, отбрасывает невидимое и выбирает уровень, а рисует через mesh-шейдеры и indirect-аргументы. Те же списки принимают экземпляры деревьев, кустов и камней; дальние деревья заменяются импосторами без скачка силуэта.

**По книге** — [подготовка тайлов и структура мира](reading-guide.md#02-ландшафт). Для пакетного обновления — §16.6.2 (с. 1061) из [маршрута 03](reading-guide.md#03-вода).

## Контракт

Потребляет: `clusters.bin` и правило среза из 02.3, группы `Placement` из 02.4.

Создаёт:

- Иерархию для обхода на GPU: дерево ограничивающих объёмов над группами кластеров (как BVH Nanite), обход в compute с очередью узлов (persistent threads) — без возврата на CPU.
- Видимые списки кластеров и экземпляров с фиксированной ёмкостью и счётчиком переполнения; буфер indirect-аргументов.
- Отрисовку кластеров object + mesh шейдерами Metal 4: object-шейдер отсекает кластер, mesh-шейдер выдаёт его вершины и треугольники. Для сравнения — путь «экземпляр = кластер» из 02.3 через indirect.
- Стадию `compute output → indirect args / object read` в планировщике проходов.

## Порядок реализации

1. **Срез на GPU.** Перенести правило 02.3 в compute: обход дерева групп, проверка экранной ошибки и пирамиды видимости, запись видимых кластеров. Сверить список с CPU-эталоном на контрольных камерах — совпадение до кластера.
2. **Indirect и mesh-шейдеры.** Отрисовка видимых кластеров через `drawMeshThreadgroups` с indirect-аргументами; сравнить с путём 02.3 по времени GPU и CPU.
3. **Экземпляры.** Отсечение и выбор LOD деревьев, кустов и камней 02.4 тем же compute; группировка по mesh/material; импосторы с плавным переходом (dither).
4. **Синхронизация и отладка.** Барьеры compute → indirect read через `frame_graph`, счётчики (проверено, отсечено, нарисовано, переполнение) в заголовке и отчёте.

## Проверка готовности

- Список видимых кластеров на GPU совпадает с CPU-эталоном 02.3 на 6 контрольных камерах; кадры совпадают.
- Нулевое и максимальное число видимых кластеров и экземпляров обрабатываются корректно; при переполнении счётчик ненулевой, записи за пределы нет.
- CPU-время кадра на Якусиме не зависит от числа кластеров (≤ 0,3 мс на рельеф); GPU-выбор ≤ 0,5 мс при 1920 × 1080.
- Переход дерева в импостор без заметного скачка силуэта. В GPU capture видны барьеры и стоимость отсечения.
