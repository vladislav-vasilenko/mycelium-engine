# 02.6. Отсечение перекрытием (Hi-Z)

[К этапу 02](02-terrain-biomes.md) · [К карте этапов](README.md)

**Зависит от** — [02.3. Отсечение и уровни детализации](02-3-terrain-lod.md), [02.5. Отсечение на GPU, indirect и импосторы](02-5-terrain-gpu-culling.md).

**Результат** — то, что закрыто холмом, скалой или берегом, не рисуется. Решение принимает GPU по иерархической карте глубины, без участия CPU и без задержки в кадр. Для кластеров рельефа, деревьев и камней за склоном отпадает работа mesh- и фрагментного шейдеров — как двухпроходное отсечение Nanite.

**По книге** — [подготовка тайлов и структура мира](reading-guide.md#02-ландшафт).

## Контракт

Потребляет: кластеры и их границы из 02.3, обход на GPU, видимые списки и indirect-аргументы из 02.5, глубину сцены.

Создаёт:

- Hi-Z — пирамида глубины: mip-уровни, где каждый тексел хранит самую дальнюю глубину четырёх текселей уровнем ниже (для reversed-Z — минимум).
- Проверку `occluded(aabb)`: проекция границ объекта на экран, выбор mip по размеру проекции, сравнение ближайшей глубины объекта с Hi-Z.
- Двухпроходное отсечение: проход 1 рисует то, что было видно в прошлом кадре, строит Hi-Z; проход 2 проверяет остальное по новой Hi-Z и дорисовывает вновь открывшееся.
- Счётчики: проверено, отсечено фрустумом, отсечено перекрытием, дорисовано во втором проходе.

## Порядок реализации

1. **Пирамида глубины.** Compute строит Hi-Z из буфера глубины кадра: уровень 0 — копия, каждый следующий — свёртка 2 × 2 с выбором дальней глубины. Неквадратный размер и нечётные стороны обрабатываются без потери покрытия. Отладочный вид уровней.
2. **Проверка объектов.** Для кластеров рельефа 02.3 и экземпляров 02.5 — проекция AABB, выбор mip так, чтобы прямоугольник покрывал не больше 2 × 2 текселей, сравнение. Объекты, пересекающие ближнюю плоскость, считаются видимыми.
3. **Двухпроходная схема.** Список «видимо в прошлом кадре» хранится на GPU. Проход 1 рисует его и строит Hi-Z, проход 2 проверяет остальные объекты. Синхронизация записи списков и indirect-аргументов — через `frame_graph`.
4. **Аппаратные запросы для сравнения.** Опыт с occlusion queries Metal (`visibilityResultBuffer`) для крупных объектов: ответ приходит с задержкой в кадр. Сравнить с Hi-Z по числу отсечённых объектов и артефактам при резком повороте.
5. **Отладка.** Вид Hi-Z по уровням, подсветка отсечённых объектов в режиме «показать всё», счётчики в заголовке и в отчёте.

## Проверка готовности

- На контрольной камере, где холм закрывает долину, перекрытием отсекается не меньше 50 % экземпляров за холмом; кадр совпадает с кадром без отсечения (сравнение изображений, расхождение 0 пикселей вне допуска на сглаживание).
- При резком повороте на 180° нет кадра с «пропавшими» объектами: второй проход дорисовывает открывшееся.
- Объекты у ближней плоскости и крупнее экрана никогда не отсекаются.
- Время построения Hi-Z и проверок записано в отчёте. Цель — ≤ 0,3 мс GPU при 1920 × 1080 и выигрыш в общем времени кадра на сценах с лесом.
